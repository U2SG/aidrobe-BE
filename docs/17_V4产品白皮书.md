## 0. 执行摘要

Aidrobe 是一个基于真实衣橱、现实状态、时间压力和个人审美的 AI 穿搭决策助手。

传统衣橱 App 解决的是“我有什么衣服”，AI 穿搭 App 解决的是“理论上可以怎么搭”。Aidrobe 要解决的是更具体、更高频、更刚性的场景：

> 我现在要出门了，基于我已有的、找得到的、能穿的衣服，哪一套最适合？

Aidrobe V4 将产品从早期“衣物识别 + 今日推荐”的 MVP，升级为一个完整的系统：

```text
多来源内容摄取
→ 真实衣橱建模
→ 个人风格学习
→ 时间敏感推荐
→ 穿搭反馈进化
→ 衣橱洞察与消费决策
```

产品的核心差异化不是“AI 能搭配”，而是：

```text
AI 知道你有什么、在哪里、能不能穿、现在来不来得及、你是否真的会穿。
```

## 1. 产品愿景

Aidrobe 的长期愿景是成为每个用户的个人穿搭操作系统。

它不只是衣橱管理工具，也不是单次 AI 生图工具，而是持续理解用户真实衣橱、审美偏好、生活节奏和消费习惯的个人风格基础设施。

未来的 Aidrobe 应该能回答：

- 今天上班穿什么？
- 还有 20 分钟出门，最快不出错的搭配是什么？
- 这件衣服还能怎么搭？
- 我最近是不是总穿同一种颜色？
- 我买这件新衣服会不会和已有衣服重复？
- 我下周出差 3 天该带什么？
- 我想穿得更利落，现有衣柜能不能做到？

产品愿景：

> 让用户不再被衣橱拖累，而是让衣橱每天主动服务她的生活。

## 2. 问题定义

### 2.1 用户问题

目标用户通常不是完全不会穿，而是面临四类问题：

#### 1）早晨决策疲劳

用户在上班、上学、约会、出差等场景前，需要快速决定穿什么。她可能有很多衣服，但仍然觉得“没有衣服穿”。

#### 2）衣橱信息不可见

真实衣柜中的衣服分散在主衣柜、抽屉、收纳箱、鞋柜、行李箱中。用户不知道自己到底有哪些单品、哪些可穿、哪些待洗、哪些已经很久没穿。

#### 3）搭配推荐不可执行

很多 AI 推荐看起来合理，但忽略了现实约束：

- 衣服是否待洗
- 是否需要熨烫
- 是否在换季箱里
- 鞋包是否容易取到
- 当前剩余时间是否足够

#### 4）风格偏好难以表达

用户可能说不出自己喜欢什么风格，但她会收藏小红书、抖音、淘宝、Pinterest、杂志截图。现有工具很少能把这些外部灵感映射回她自己的真实衣橱。

---

## 3. 解决方案

Aidrobe 的解决方案可以概括为四句话：

1. 用多来源导入快速建立真实衣橱。
2. 用结构化标签、图片、embedding 和状态字段保存衣物信息。
3. 用时间、位置、状态、天气、场景和审美偏好生成可执行穿搭。
4. 用反馈、穿着历史和外部灵感持续学习用户风格。

核心链路：

```text
拍照 / 链接 / 分享 / 截图 / 订单 / 灵感图
→ 异步导入任务
→ 衣物识别 / 风格抽取
→ 用户确认
→ 衣橱入库
→ 每日推荐
→ 用户穿着与反馈
→ 风格画像进化
```

## 4. 产品定位

### 4.1 一句话定位

Aidrobe 是一个基于真实衣橱和出门时间的 AI 穿搭决策助手。

### 4.2 更完整的定位

Aidrobe 通过多模态 AI 建立用户真实衣橱档案，结合衣物状态、存放位置、时间压力、场景、天气和个人审美，在用户出门前给出可直接执行的穿搭方案。

### 4.3 不做什么

Aidrobe 早期不应定位为：

- 泛泛的时尚社区
- 纯 AI 生图工具
- 电商导购平台
- 只做衣物记账的库存工具
- 完全依赖人工造型师的服务产品

## 5. 核心用户

### 5.1 初始目标用户

- 20–35 岁女性上班族
- 对穿搭有要求，但早晨时间有限
- 有一定数量衣服，但管理混乱
- 喜欢看小红书、抖音、淘宝、Pinterest 等穿搭内容
- 愿意使用 AI，但希望推荐真实可执行

### 5.2 用户心理

她们不一定想成为时尚达人，而是希望：

```text
更快、更稳、更像自己地出门。
```

### 5.3 高频场景

| 场景 | 用户问题 | Aidrobe 价值 |
|---|---|---|
| 普通上班日 | 不想花时间想穿搭 | 给出稳妥方案 |
| 起晚赶时间 | 来不及翻衣柜 | 给出最快可执行方案 |
| 重要会议 | 想更正式但不僵硬 | 给出场景适配方案 |
| 周五/约会 | 想有一点风格 | 给出更有表达的方案 |
| 出差旅行 | 不知道带什么 | 生成 packing list |
| 购物前 | 想买但怕重复 | 评估与已有衣橱匹配度 |

## 6. V4 产品系统

Aidrobe V4 由六个核心系统组成。

### 6.1 多来源导入系统

支持输入：

```text
camera_image
album_image
shared_image
screenshot
product_link
order_screenshot
receipt_email
style_link
style_image_batch
pdf_magazine
```

目标：降低衣橱建库成本。

所有输入都进入统一异步任务系统：

```text
POST /v1/import-tasks
→ queued
→ fetching / processing
→ waiting_confirm
→ confirmed / failed
```

### 6.2 衣橱知识库

每件衣物由三层信息构成：

#### 图像层

- original_image_url
- cover_image_url
- cutout_image_url
- mask_url

#### 结构化层

- category
- sub_category
- color_main
- color_secondary
- material
- season_tags
- style_tags
- formality_score
- status
- location
- time_cost_level

#### 向量层

- image_embedding
- text_embedding
- style_embedding

### 6.3 风格学习系统

将原来的 `style/inspirations` 升级为 `style_sources`。

支持：

```text
image
image_batch
link
screenshot
pdf
magazine
shared_content
```

每个风格来源有状态：

```text
queued / processing / learned / failed
```

输出：

```text
style_tags
color_palette
preferred_silhouette
preferred_formality
avoid_tags
confidence_score
learned_summary
```

### 6.4 时间敏感推荐系统

每日推荐不是简单三套，而是三种决策策略：

```text
safe：最稳妥
fast：最省时间
stylish：更有风格感
```

同时根据距离出门时间动态调整：

```text
relaxed：> 90 分钟，可推荐更完整造型
standard：30–90 分钟，推荐稳妥方案
rushed：15–30 分钟，优先低取衣成本
instant：< 15 分钟，只给最快一套
```

### 6.5 穿搭反馈系统

用户反馈包括：

```text
wear
like
dislike
skip
too_formal
too_casual
too_complex
not_my_style
not_weather_fit
hard_to_find
```

系统学习的不只是“喜欢/不喜欢”，而是：

```text
用户喜欢什么、实际会穿什么、在什么场景下会妥协。
```

### 6.6 衣橱洞察系统

V4 增加长期留存能力：

- 本月最常穿单品
- 闲置超过 60 天单品
- 重复搭配
- 成本/穿着次数
- 色彩画像
- 风格趋势
- 购物重复提醒
- 换季整理建议

```text

  └─ Push Notification

Async Workers
  ├─ Image Processor
  ├─ Link Parser
  ├─ OCR / Screenshot Parser
  ├─ Vision Tagger
  ├─ Embedding Generator
  ├─ LLM Summarizer
  ├─ Style Learner
  └─ Recommendation Generator

Storage
  ├─ Object Storage
  ├─ PostgreSQL
  ├─ Vector DB / pgvector
  ├─ Redis Cache
  └─ Event / Analytics Store
```

### 8.2 核心原则

- 上传与识别分离。
- 同步 API 与异步任务分离。
- 推荐召回与 LLM 解释分离。
- 衣物事实数据与风格偏好数据分离。
- 用户可见结果与模型内部评分分离。

## 9. 核心技术路线

### 9.1 图片理解

V4 不依赖单一模型，而采用组合链路：

```text
图片上传
→ 图片标准化
→ 背景移除 / 分割
→ 服装分类
→ 颜色/材质/风格抽取
→ embedding 生成
→ 用户确认
```

### 9.2 链接导入

```text
source_url
→ resolve short link
→ domain adapter
→ metadata / og:image / json-ld
→ screenshot fallback
→ image extraction
→ vision tagging
→ candidate item
```

### 9.3 风格学习

```text
style source
→ content extraction
→ outfit / garment detection
→ style tag extraction
→ palette / silhouette / formality summary
→ style profile update
```

### 9.4 推荐生成

```text
1. 硬过滤：status、category、season、weather、scene
2. 候选生成：top + bottom + shoes + outerwear
3. 评分排序：utility、time_cost、aesthetic、freshness、weather、repetition
4. 多样性约束：避免 3 套太像
5. LLM 文案：生成解释，不负责凭空搭配
6. 缓存：今日推荐写入 Redis / DB
```

## 10. 推荐评分模型

建议 V4 内部评分：

```text
final_score =
  0.25 * utility_score
+ 0.20 * time_cost_score
+ 0.20 * aesthetic_score
+ 0.15 * weather_score
+ 0.10 * freshness_score
+ 0.10 * confidence_score
- repetition_penalty
- unavailable_penalty
```

### 10.1 time_cost_score

由以下因素决定：

- location
- status
- 是否需熨烫
- 是否鞋包跨位置
- 当前离出门时间

### 10.2 aesthetic_score

由以下因素决定：

- 用户点赞历史
- style_sources 学习结果
- 颜色偏好
- 廓形偏好
- 场景偏好

### 10.3 utility_score

由以下因素决定：

- 品类完整度
- 场景正式度
- 百搭性
- 用户历史采用率

## 13. 竞争壁垒

### 13.1 数据壁垒

Aidrobe 长期积累的是用户真实衣橱、状态、位置、穿着记录、偏好反馈、风格来源，而不是单次聊天记录。

### 13.2 场景壁垒

产品聚焦“出门前决策”，比泛衣橱管理更高频、更明确。

### 13.3 现实约束建模

衣物状态、存放位置、取衣成本、时间压力是竞品较弱的部分。

### 13.4 多来源摄取能力

中国用户的风格输入分散在小红书、抖音、淘宝、朋友圈、截图和购物记录里，多来源解析能力会成为本地化壁垒。

### 13.5 反馈闭环

系统不仅知道用户喜欢什么，还知道用户最后真的穿了什么。

## 14. 风险与应对

| 风险 | 说明 | 应对 |
|---|---|---|
| 用户不愿录衣服 | 建库成本高 | 多来源导入、批量上传、链接和截图导入 |
| 识别错误 | 类别/颜色错会影响推荐 | AI 初稿 + 用户确认 + 可编辑 |
| 推荐不可信 | AI 推荐不符合现实 | status/location/time_cost 硬过滤 |
| 平台链接不稳定 | 电商和内容平台反爬/结构变化 | adapter + fallback + 用户截图 |
| 隐私敏感 | 衣橱和身体图像属于私人数据 | 最小化采集、加密、可删除、虚拟试穿可选 |
| 商业化伤害信任 | 导购可能让用户觉得推荐被污染 | 明确区分推荐和购物建议 |

## 16. 北极星指标

Aidrobe 的北极星指标不是“衣服录入数量”，而是：

> 每周用户实际采用 Aidrobe 推荐穿搭的次数。

### 16.1 核心漏斗

```text
注册
→ 设置出门时间
→ 录入 10 件以上衣物
→ 收到今日推荐
→ 打开推荐
→ 点击今天穿这套
→ 提交反馈
→ 次日继续使用
```

### 16.2 关键指标

- 首日录入件数
- 首周录入件数
- 导入成功率
- 今日推荐打开率
- 推荐采用率
- 反馈率
- 7 日留存
- 每周穿着记录数
- style source 添加数

## 18. 结语

Aidrobe 的机会不在于做一个“更漂亮的衣橱 App”，也不在于简单把 LLM 接进穿搭推荐。

真正的机会在于：

```text
把真实衣橱、现实约束、时间压力和个人风格偏好连接起来，成为用户每天出门前真正会用的决策系统。
```

如果 V1 验证“用户愿意录衣服并看推荐”，V2 验证“推荐现实可执行”，V3 验证“系统越来越像我”，那么 V4 的目标就是：

> 成为用户个人衣橱和风格生活的长期操作系统。
