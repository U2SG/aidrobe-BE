# 当前设计中的购买判断与会话接续

这一批把购买判断接入已经建立的设计会话。用户考虑一件新衣服时，服务使用当前已接受的条件判断；结果和购买选择留在原会话，后续设计可以接着使用这些信息。

## 已实现的行为

- 购买入口携带原会话 ID、当前 brief 版本和独立请求 ID。刚更新条件、尚未生成新搭配时，使用最新 brief。
- 锁定衣物进入证据窗口，排除衣物在限制条数前过滤。新候选与锁定衣物冲突时，说明冲突并保留锁定衣物。
- 独立购买判断保持原有首次结果；与设计关联的判断允许同一候选按不同版本分别评估，历史结果不被改写。
- 每个结果保存当时的条件、来源、时间以及已使用／尚未核验的维度。携带参考图、日期或自由文本，不等于已经核验这些条件。
- “打算买／先不买／再想想”及取消选择存到服务端；选择与评估快照分开存储，重复提交相同选择保留原时间和来源。
- 原会话恢复按创建时间显示购买结果；打开历史卡片按确切 decision ID 读取，不重新计算。
- 明确、无歧义且对象唯一的购买选择可在续聊中保存。多件候选可能被指代时不猜测目标。
- 购买候选始终不是已拥有的衣物，单次购买选择不能直接成为长期偏好。
- 已删除／遗忘的来源不再进入后续购买上下文；参考派生回答也不进入 recent、summary 或 last-outfit 文本。
- 上传完成后保留 object key；候选创建和购买评估分别使用稳定请求 ID。失败重试复用原请求，切换图片或确认新条件才创建对应的新请求。
- 旧账号任务和旧会话回调不得覆盖当前界面；读取历史失败时保留目标会话的失败状态。

接口细节见 [v3-p0-contract.md](../v3-p0-contract.md) §5.4，机器契约由 GitHub CI 生成。

## 本机 Simulator 验收

配套 iOS 在既有 `WalkthroughTests` 中增加购买接续流程，复用现有 DEBUG 样例图片入口。它验证真实上传、候选、评估、选择和会话恢复的调用链；样例图不能证明真实服装识别或推荐质量。

需要验收的实际体验：

1. 在同一段会话中建立设计，锁定一件已有衣物，并排除另一件。
2. 从当前设计进入购买判断，使用真实服装照片；确认当前条件、识别结果和证据中的衣物身份。
3. 选择“再想想”，返回原会话；检查卡片的判断、选择和当时版本。
4. 继续说“先不买了，继续用已有衣服搭”，检查保存的选择及新搭配仅使用衣橱中的衣物。
5. 重启应用、恢复会话并重新打开原结果；检查历史快照未改变。
6. 修改条件后再次评估；确认新结果属于新版本，原结果仍可回看。
7. 核对浅色／深色界面，条件较长、无可行搭配、服务不可用及重试状态。

本轮尝试本机执行时，Codexless 返回实际项目未显式受信任，权限上限为 `read-only`；只读 `simctl` 查询也因缓存写入与 CoreSimulator IPC 被拒绝。代码与 CI 完成情况以配套 PR 的验证记录为准，不能把 CI 的模拟器目标构建当成已通过本机交互验收。

## 当前能力边界

结果可以使用已有衣橱、结构化场景／风格标签与锁定／排除条件。尺码与合身、价格相对预算、目标日期天气、候选自身风格、参考图视觉相似度以及自由文本的完整语义仍按响应标为未核验。后续扩展应逐项加入真实证据和回归，不用措辞把未知包装成结论。

迁移 0058 保留评估、选择和请求身份。若已有与设计关联的评估、已保存的购买选择或候选重试身份，迁移会在改变任何结构前明确拒绝降级；仅旧流程数据可以正常回退。不能通过删除用户记录来让降级成功。
